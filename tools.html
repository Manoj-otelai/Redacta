What this is

The page publishes operations, not document contents.

WebMCP is how Redacta talks to an agent without handing it the file. The agent does not scrape the DOM and it is not given the PDF. It is offered ten named operations — inspect, scan, redact, verify, export — and every answer is metadata. The tool API is the privacy boundary.

src/ui.js · registerTools

modelContext.registerTool({
  name,
  description: TOOL_DESCRIPTIONS[name],
  inputSchema: TOOL_SCHEMAS[name],
  execute: (input) => execute(name, input)
});

Native WebMCP uses document.modelContext or navigator.modelContext. Missing either, Demo Mode puts the same ten functions on window.

How it is built

The boundary is code, not a promise

Registration, schemas, projection, confirmation, the Demo Mode fallback, and verification are six separate pieces. None of them return document text.

src/ui.js

Register the ten tools

registerTools() looks for document.modelContext.registerTool, then navigator.modelContext.registerTool. Each tool is registered with name, description, inputSchema, and execute. Agent calls go through executeTool(name, input, "agent").

src/tools.js

Schemas that refuse contents

TOOL_SCHEMAS and TOOL_DESCRIPTIONS live next to the implementations. Every description states the tool never returns document contents or sensitive values. The execute functions return counts, IDs, and projected rows — not matched strings.

src/registry.js

A fixed whitelist

Raw detector hits stay in an in-memory registry. Anything that crosses to the agent is projected through SAFE_FIELDS: id, type, confidence, status, origin, page. Values, locations, and offsets are not on that list.

src/ui.js · requestConfirmation

Mutations stop for a human

When callSource is agent, applyRedactions, exportSanitizedDocument, registerCustomPattern, and redactField call in-page requestConfirmation. Deny, or wait out the minute, and the tool returns denied — nothing is changed.

Demo Mode

Same tools without the flag

If native WebMCP is missing, the status chip reads Demo Mode. The same ten functions are assigned onto window and callable from the Console pane. Same schemas, same projection, same confirmation gate.

src/verify.js · src/tools.js

Three checks on the bytes

Verification re-reads the generated artifact. It reports extractableFindings (detectors still fire), unmaskedRegions (findings still pending), and originalValuesFound (raw strings still appear). Export stays blocked until all three are zero, then re-checks the SHA-256 digest.

The ten tools

What the agent gets. What it never gets.

Each tool is a capability. The privacy punch is in the return value — metadata only, every time.

inspectDocument

A status check, not a read. Reports what is loaded the way a librarian will tell you the shelf and the page count without opening the book.

Gets fileType, filename, documentSize, pageCount, processingStatus. Never a character of the document.

scanDocumentPII

Runs the local detectors — optionally scoped to categories — in a Web Worker. Hits are stored in the registry; the agent only sees the projected rows.

Gets totalDetected and findings with id, type, confidence, status, origin, page. Never matched values, locations, or offsets.

getFindingDetails

One finding, by id, through the same whitelist. Use it when the agent needs a single row, not another full scan.

Gets type, confidence, status, origin, page. Never the value, location, or character offsets.

applyRedactions Human approval

Marks selected findings redacted and builds a sanitized artifact locally. Agent-initiated calls open an in-page confirmation and wait.

Gets totalRedacted, maskMode, projected findings. Never document contents or the masked strings.

verifyRedaction

Re-reads the generated file. App state is not treated as proof. A rasterized PDF has no text layer, so a text rescan alone would lie — that is why coverage and original-value checks exist.

Gets passed, remainingFindings, extractableFindings, unmaskedRegions, originalValuesFound, per-category counts. Never remaining values or document text.

exportSanitizedDocument Human approval · blocked until verify

Starts a local download of the verified artifact. Blocked if verification has not passed, or if the digest no longer matches the file still in memory.

Gets filename, size, verified: true. Never the file bytes in the tool response.

getVerificationCertificate

Metadata-only proof for a passing artifact: an RDCT-… id, SHA-256 digest, issued time, and the numeric checks. Stale artifacts are rejected.

Gets certificateId, digest, document metadata, check counts. Never document contents or finding values.

registerCustomPattern Human approval

Validates a regex, then registers it as a local detector (max 5). Unsafe, empty, or slow patterns are rejected before the confirmation appears.

Gets name, totalPatterns. Never document contents or the strings the pattern later matches.

listStructuredFields

JSON and CSV only. Lists keys or columns with how often they occur and how many detections overlap them — enough to choose a field, not enough to read it.

Gets format and fields[{field, occurrences, detectedFindings}]. Never cell or leaf values.

redactField Human approval

Redacts every string value of one JSON key or CSV column so the artifact stays valid structured data. Agent-initiated calls wait for confirmation.

Gets field, valuesRedacted, redactedIds, totalRedacted, projected findings. Never the values that were redacted.
